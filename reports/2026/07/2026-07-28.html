Claude Code · Sub-Agents Claude Code Sub-Agents: Parallelize Complex Tasks with Spawned Workers

Claude Code's sub-agent spawning is the most underused power feature for Monday morning productivity. Instead of sequentially handling a complex task, spawn parallel workers that each handle a piece — dramatically reducing wall-clock time for multi-file operations. The pattern: (1) Use /spawn for independent subtasks: when refactoring a feature that touches 5 files, spawn a sub-agent for each file with clear instructions: "Refactor UserRepository to use async/await, keep existing interface, add error handling". Each sub-agent works in isolation, then you review all diffs together. (2) The Supervisor pattern in practice: your main session acts as supervisor — describe the high-level goal, let Claude decompose it, then spawn workers for each component. If compilation fails, the sub-agent self-corrects before reporting success. Trending Architecture-as-Code: Define, Validate, and Enforce System Design in Version Control

A methodology gaining serious traction in July 2026: Architecture-as-Code (AaC) — defining your system's architectural rules, constraints, and patterns in machine-readable, version-controlled formats (YAML, HCL, or DSLs) that can be automatically validated against your actual codebase. Unlike architecture diagrams that rot in Confluence, AaC rules are living enforcement mechanisms that break your build when violated. How it works in practice: (1) Define architectural rules: rule: "no direct dependency from Presentation layer to Data layer" — expressed as patterns matching import statements, module boundaries, or dependency graphs. (2) Fitness functions run in CI: on every PR, automated checks verify the code adheres to declared architecture. A developer adding a direct database call from a SwiftUI View gets an immediate CI failure with explanation. (3) Architecture drift detection: weekly reports show where the implemented architecture has diverged from the declared design — surfacing tech debt before it becomes structural. (4) AI agent awareness: your AaC rules file becomes context for AI coding agents. Add it to your CLAUDE.md: "Architecture rules are defined in .architecture/rules.yaml — never generate code that violates these rules." The agent now respects your architectural boundaries automatically. For iOS teams: define rules like: "ViewModels never import UIKit," "Repository protocols live in Domain module," "No Combine in SwiftUI views (use @Observable instead)."
