Best of Week · Agent Harness The Unified Agent Harness: Compose Hooks + Skills + MCP + Sub-Agents Into One Reviewed Boundary

The week's recurring thread across Mon/Fri tips was that production agents need a single harness, not scattered features. The synthesis: (1) Hooks enforce invariants at lifecycle points (format on write, block secrets, test on stop); (2) Skills package repeatable multi-step workflows as versioned playbooks; (3) MCP servers ground the agent in your real system (design tokens, API contracts, dependency graph); (4) Sub-agent orchestration fans out parallel work with per-worker tool budgets. The key insight: these four compose into one AgentHarness boundary that you review, test, and version as a unit — so agent lifecycle, cost, and safety live in one auditable place, not bolted onto ad-hoc prompts. For a Binance iOS team, this is the layer where compliance, blast-radius limits, and eval gates all attach. Claude Code agents →

On-Device · Model Selection The 2026 On-Device Model Decision Tree: Foundation Models vs Core AI vs MLX vs Open-Weight LFM

Tuesday's Core-AI-vs-CoreML-vs-MLX tip now has a fourth branch: open-weight small models like Liquid AI's LFM2.5-2.6B (released this week, 2.69B params, 128K context, native tool-calling, 220 tok/s on M5 Max under 2.5GB). The refreshed decision tree: (1) Apple Foundation Models (.core / .coreAdvanced) — zero-download, zero-cost, fully private; default for Apple-model generative features on iPhone 15 Pro+. (2) Core AI — Apple's new unified framework for neural + generative, best for new greenfield features. (3) MLX Swift — fastest decode for a specific open model you ship weights for (Qwen/Llama-class). (4) Open-weight LFM/SmolAgents — when you need agentic tool-use on-device with your own weights and a permissive license. Abstract behind a ModelRuntime protocol so the choice is a config swap, and benchmark on your lowest-supported device, not your dev machine. MLX Examples →

Evals · The Missing Pillar Instrument Agent Runs With Cost + Completion + Safety Metrics Before You Ship to Production

The week's ROI reality-check story (agentic tools save ~1 day/engineer/week but many projects face cancellation without governance) lands on one actionable gap: most teams ship agents without an eval harness. The minimum viable observability for any production agent: (1) Cost per task — tokens × price, logged per run; (2) Completion rate — did the agent finish within its tool-call budget, or hit the ceiling; (3) Safety events — tool calls that hit your egress allow-list denials or blast-radius gates; (4) Structured session traces — goal, plan, tool calls, outcome, user correction — so you can eval offline and (per Friday's "Dreaming" concept) eventually learn from them. Without these four, you can't tell productivity from luck. Treat the eval harness as the first thing you build, not the last. Building effective agents →

🔥 Hot Industry Concepts
Trending Portable Tool Standards: MCP vs Agent Plugins — The Interop Layer War

A concept crystallizing this week: the AI industry is racing to define a portable tool-interoperability layer, and two competing standards are now live — Anthropic's Model Context Protocol (MCP) (stateless since Jul 28, widely adopted by Claude/Gemini/Codex) and Google-backed Agent Plugins 1.0.0 (vendor-neutral, supported by Amazon/Microsoft/OpenAI). Why it matters NOW: (1) whichever wins becomes the "USB-C of AI tools" — write a tool once, run it across every agent client; (2) the stakes are lock-in: a tool written to one standard is cheaper to reuse but harder to migrate; (3) the practical hedge is a thin adapter so your tools speak both. For a Binance iOS team exposing design tokens / API contracts as agent tools, target MCP first (mature, shipped) and add an Agent Plugins adapter as the spec stabilizes. The era of bespoke, per-vendor tool integrations is ending. MCP spec →

Trending Post-Quantum Account Security: Sui Adds Quantum-Safe Signatures

Sui announced it will add post-quantum signature schemes for quantum-safe accounts — the first major L1 to ship PQ-resistance at the account layer, addressing the "store now, decrypt later" threat where adversaries harvest encrypted transactions today to break them once quantum computers mature. Why it matters: (1) post-quantum crypto (PQC) migration is moving from NIST standards (2024) into shipped protocol features — the timeline is years, not decades; (2) for any wallet or custody integration, PQ-readiness is becoming a procurement and compliance question, not a research topic; (3) the architectural shift is a hybrid signature period (classical + PQ in parallel) — your signing UX and key-management code need to handle both without doubling user friction. For your team: audit how your self-custody / wallet features would adopt a hybrid scheme, and track Sui's implementation as the reference. Sui →
