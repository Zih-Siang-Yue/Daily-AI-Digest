ONNX · Cross-Platform Ship One ONNX Model, Run It on iOS, Android & Server via the Core ML Execution Provider

If you maintain inference across both iOS and Android, ONNX Runtime Mobile with the Core ML Execution Provider is the cross-platform escape hatch from writing the same model twice. The workflow: export your PyTorch/Torch model to ONNX once, then on iOS the Core ML EP routes compute to the Neural Engine/GPU automatically (falling back to the CPU EP), while on Android the NNAPI EP does the equivalent. For a Binance iOS team that also ships an Android app, this cuts model-maintenance cost in half — one weights file, one version, one eval suite. Caveat: the Core ML EP doesn't support every op, so run the ONNX CoreMLOptions compatibility check in CI and keep a Core ML-native fallback for unsupported subgraphs. On-Device · Memory Give Your On-Device Agent Persistent Memory With a Local Vector Store + Episodic "Dream" Replay

A pattern surfaced on Hacker News this week ("Use Dreams to create memories your AI agent can access") operationalizes Anthropic's "Dreaming" concept (Aug 7) on-device: persist episodic memory as structured (goal, action, outcome, user-correction) records in a local SQLite store, index them with a small on-device embedding model (MLX or Natural Language framework's NLEmbedding), and replay a curated slice offline to refine future behavior. For an iOS feature, this means a privacy-preserving agent that genuinely gets better the more you use it — with zero data egress, because the memory never leaves the device. The hard part is the review gate: don't let "learned" changes apply silently. Ship a read-only memory viewer in your debug menu so you can audit what the agent "remembers," and cap the replay set to the last N sessions to bound compute. MCP · Security

"GhostSplice" Attack Splits Malicious Instructions Across MCP Tools to Steal Secrets

The ASSET Research Group disclosed "GhostSplice," a new attack against AI coding assistants using the Model Context Protocol: instead of one obviously-malicious instruction, the attacker splits the harmful request into multiple benign-looking fragments placed in different MCP channels the agent already uses. The agent stitches the fragments together in its normal operation and inadvertently executes the command — exfiltrating SSH keys, env secrets, source, and customer data. Disclosed via controlled tests with fake credentials (no CVE yet, pending coordinated disclosure). Why it matters: (1) this is a new class of prompt-injection that defeats per-tool sanitization — each fragment looks harmless in isolation; (2) it directly extends the "pre-approved-host exploit" pattern from Aug 9 and the Claude Code CVE from Aug 9, but attacks the tool-output-to-tool-input boundary rather than the egress allowlist; (3) the defense is the ASSET group's recommendation: treat MCP server output as data, not instructions, and prevent one tool's output from flowing unchecked into another tool's arguments — wire this into your PreToolUse hooks today. Security Cross-Tool Prompt-Stitching Attacks: The New Agent-Vulnerability Class

A new vulnerability class crystallized this week via the GhostSplice disclosure: cross-tool prompt-stitching, where an attacker fragments a malicious instruction across multiple MCP tool outputs that are individually benign but combine into a harmful command when the agent stitches them in its working context. This is distinct from the pre-approved-host exploit (Aug 9, which attacked egress) and the Claude Code CVE (Aug 9, which attacked an allowlist) — GhostSplice attacks the data-flow boundary between tools. Why it matters NOW: (1) it defeats naive per-tool sanitization — each fragment passes validation, the combination doesn't; (2) it generalizes the "treat tool output as untrusted data, not instructions" principle into a hard requirement for any agent with multiple MCP servers; (3) the concrete defense pattern: enforce a data/instruction separation boundary in your harness (tool output is tagged as data, never re-executed as a prompt), and add a lint rule that flags when one tool's output flows into another tool's arguments unchecked. Expect a wave of CVEs in this class — build the review gate now. GhostSplice analysis →
