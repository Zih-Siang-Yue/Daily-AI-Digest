Inference Routing · Infra Tier Your Inference by Latency Budget: Route Hot Paths to Ultrafast, Cold Paths to Cheaper Models

OpenAI's new Ultrafast mode runs GPT-5.6 Sol at up to 14× speed (≈750 output tok/s) via Cerebras silicon — fast enough that a full agent tool-call round-trip fits inside a single UI frame. The infra pattern this unlocks for an iOS team: stop pinning one model per feature and instead route by latency budget. Map every agent call to a tier — (1) hot interactive paths (reply suggestions, autocomplete, on-device fallback orchestration) → Ultrafast or Foundation Models on-device; (2) warm background tasks (summarization, classification) → standard GPT-5.6 Sol / Sonnet 5; (3) cold batch (eval runs, doc indexing) → cheapest capable tier. Gate the routing in a thin InferenceRouter so a tier swap is a config change, not a code change, and log per-tier token spend so cost stays observable (Aug 11's cost-overage lesson). RAG · Data/Instr Separation Treat Retrieved RAG Chunks as Untrusted Data, Never as Instructions — Extend the GhostSplice Defense to Retrieval

Thursday's GhostSplice disclosure (cross-tool prompt-stitching) generalizes directly into your RAG pipeline: a poisoned doc in your vector store is the same threat shape as a malicious MCP tool output. The hard rule: retrieved chunks must enter the context window tagged as data, and the system prompt must forbid acting on any instruction found inside them. Concretely — (1) wrap every retrieved passage in a delimiter the model is instructed to treat as read-only context; (2) add a PostToolUse-style guard that scans the assembled prompt for instruction-shaped strings inside retrieved chunks and quarantines them; (3) keep a separate "trusted instructions" channel (system + user turns only) that retrieved text can never write to. For a Binance iOS feature pulling from internal KB/support docs, this is the difference between a helpful retrieval-augmented reply and a prompt-injection-driven exfil. GhostSplice pattern →

Agent Arch · Spec-as-Source Version Your Agent Intent Specs Like Code — The Spec Becomes the Reviewed Boundary for Autonomous Runs

The through-line from Anthropic's intent-driven development (Aug 9) and OpenAI's "assistance to execution" enterprise report (Aug 13) is now concrete: for any agent that runs autonomously (Cursor Automations, Claude Code background tasks, Codex long-running jobs), the intent spec — goal, constraints, allowed tools, success criteria — is the security and correctness boundary, not the prompt. Treat it as a reviewed artifact: one spec.yaml per agent workflow, checked into git, diffed on PR, with a CI lint that fails on missing blast-radius caps (tool-call ceiling, egress allowlist, max runtime). For iOS CI, this means an agent that "fixes a failing test" can only touch test files, can only call the test runner, and auto-aborts after N calls — all enforced by the spec, not by hoping the model behaves.
