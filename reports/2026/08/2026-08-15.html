Agent Security · Best of Week The Three-Layer Agent Containment Stack: PreToolUse Hooks + Spec-as-Source + Egress Allowlist

Synthesizing the week's security arc (GhostSplice cross-tool stitching Aug 13, spec-as-source Aug 14, egress hygiene Aug 9) into one deployable pattern. Layer 1 — a PreToolUse hook that treats every MCP tool output as data, never re-executable as a prompt (defeats GhostSplice). Layer 2 — a versioned spec.yaml per agent workflow defining goal, allowed tools, blast-radius caps (max tool calls, max runtime), and egress allowlist; the spec is the reviewed boundary, not the prompt. Layer 3 — a CI policy-lint step that fails on overly-broad allowlists or missing caps (Aug 12's polycheck pattern). For a Binance iOS CI agent that "fixes a failing test," this means: it can only touch test files, can only call the test runner, auto-aborts after N calls, and can only egress to your internal artifact store. Ship the stack as a single .agent-policy/ directory checked into git — one review surface for all three layers. GhostSplice defense →

Trending Resource-Priced Fee Markets: From EIP-1559 to SIMD-0553 — Compute-Weighted Burns as the L1 Template

A concept consolidating across this week's L1 governance: resource-priced fee markets — transaction fees tied to actual compute/resources consumed, with the base fee burned rather than paid to validators. Ethereum's EIP-1559 established the pattern (burn base fee); Solana's SIMD-0553 (vote Aug 18) extends it to compute-weighted pricing (high-failure-rate transactions pay proportionally more), projecting a 12x burn increase. Why it matters NOW: (1) resource-priced burns are becoming the default L1 economic template — any new chain (or L2) launching without one is now the exception; (2) for builders, the unit-economics shift is real: strategies that worked under flat-fee regimes (high-volume MEV, spam-ish arbitrage) become uneconomic, while genuinely useful transactions get cheaper — re-model any Solana/ETH dApp's fee assumptions; (3) the political fault line is validator revenue (burned fees = lost validator income) — watch whether SIMD-0550's inflation cut + SIMD-0553's burn pass together, as the pair determines SOL's deflationary path. Security Post-Quantum Pragmatism: Ethereum Abandons Poseidon for SHA/BLAKE — Standard Hashes Win

A concept materializing in Ethereum's Aug 15 decision: post-quantum pragmatism — the shift away from specialized "SNARK-friendly" cryptography (Poseidon hash) toward standard, battle-tested hashes (SHA-2, BLAKE2s) now that SNARK efficiency for standard hashes has caught up. The Ethereum Foundation (researcher Justin Drake) announced it will no longer use Poseidon for L1 post-quantum security, ending an 8-year research arc — not because Poseidon is broken, but because standard hashes now match its SNARK performance. Full PQ protection is targeted for 2029 via the "Lean Ethereum" roadmap. Why it matters NOW: (1) it's a concrete reversal of the "use specialized PQ crypto early" thesis — the lesson generalizes: prefer standard, widely-audited primitives until specialized ones offer a decisive, durable advantage; (2) for wallet/custody teams, the PQ migration path just simplified — you can plan around SHA/BLAKE (which your existing tooling already supports) rather than Poseidon (which required new libraries); (3) the 2029 full-PQ target is the planning horizon — any long-lived signing infrastructure (cold storage, multisig) designed today should be PQ-agile (hybrid classical+PQ) to avoid a 2028 retrofit.
