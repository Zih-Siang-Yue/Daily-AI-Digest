💡 Daily Tech Tips — Best of Week: Context & Memory as Versioned Artifacts
Best of Week · Context Engineering Treat the Agent Context Window as a Reviewed, Versioned Artifact — Not a Prompt

The week's clearest through-line, spanning context engineering (Aug 11), spec-as-source (Aug 14), and GhostSplice's data-vs-instruction boundary (Aug 13): the context an agent sees is the real security and correctness surface, not the prompt. The deployable pattern: assemble the context window from four tagged channels — (1) trusted-instructions (system + user turns only, never writable by tools or retrieval); (2) retrieved-data (RAG chunks, MCP tool output — all wrapped in delimiters the model is told to treat as read-only); (3) tool-schemas (the MCP manifest, frozen per spec); (4) conversation (history, with secret redaction). Check the assembled window into git as a context.yaml alongside your spec.yaml, diff it on PR, and add a CI lint that fails if any retrieved-data channel contains instruction-shaped strings. For a Binance iOS agent that "answers a support question using internal KB docs," this is the difference between a helpful reply and a prompt-injection-driven exfil. GhostSplice defense →

Best of Week · Agent Harness The Model-Agnostic Agent Harness Pattern: One Host, Many Models, Zero Lock-In

This week's open-agent cluster (Opencode 180K★, Prime Agent persistent memory, Spotify Xirp macOS host, Meta Muse Code) all converged on the same architecture — and it's the one to copy for a regulated Binance team. The shape: a host layer (session lifecycle, OS integration, multi-agent orchestration) that is decoupled from the model layer (75+ providers via a pluggable backend, including local models via Ollama/MLX). The payoff: swap the model per task (frontier Claude for hard reasoning, local DeepSeek-V4-Pro for proprietary-code work, on-device Foundation Models for trivial iOS paths) without rewriting the harness. Concretely, pin one open host (Opencode or Xirp), wire it to your internal model gateway, and enforce the containment stack (PreToolUse hooks + spec-as-source + egress allowlist from Aug 15) at the host layer so every model inherits the same blast-radius caps. This is the credible "never send code to a cloud agent" path — run it on a Mac Studio with a local model and your proprietary Binance code never leaves the machine. Opencode →

Best of Week · On-Device Memory Design the On-Device Agent Memory Privacy Boundary Before You Ship It

Two week-end signals — the on-device "Dream" replay pattern (Aug 13) and OpenAI's new ChatGPT "Computer History" feature (today) — make the same point: agent memory is now a first-class product surface, and its privacy boundary must be designed, not assumed. The rules for an iOS agent that learns from usage: (1) local-only by default — episodic memory (goal, action, outcome, user-correction) stays in a SQLite store indexed by NLEmbedding, never egressing; (2) explicit opt-in for any cloud sync, with a per-record toggle, mirroring how Computer History requires Pro/Business/Enterprise opt-in and excludes the EEA/UK/Switzerland at launch; (3) unencrypted-local-storage warning — OpenAI explicitly flagged that raw Computer History files on disk are not encrypted by the feature and could be read by other macOS processes; the iOS analog is to store agent memory in the app's Data Protection class .complete (encrypted at rest), not a plain file; (4) review gate — ship a read-only memory viewer in your debug menu so you can audit what the agent "remembers," and cap the replay set to the last N sessions. Anthropic Sunsets Legacy Workbench on Aug 17 + Retires 3 Experimental Prompt APIs

Anthropic is retiring its legacy Workbench and three experimental prompt APIs (/v1/experimental/generate_prompt, improve_prompt, templatize_prompt) on August 17, 2026 — tomorrow. Why it matters: (1) action today — if any of your iOS team's CI scripts or internal tooling calls the three experimental endpoints, they will return errors after Aug 17; grep your repos for experimental/generate_prompt and migrate to the Messages API or a prompt-management tool like LangSmith/PromptLayer; (2) the move to a stateless Workbench means Anthropic is exiting the "prompt management" category — if you relied on Workbench to store eval test cases, migrate them to your own system now (there is no equivalent in the new UI); (3) this is consistent with Anthropic's platform consolidation (Sonnet 5 pricing hold, Opus 4.1 retirement, inference hooks beta) — the production surface is narrowing to Messages API + Claude Code, so align your tooling to that spine.
