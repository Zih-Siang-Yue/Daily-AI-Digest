💡 Daily Tech Tips — Best of Week: The Ship-Safe Agent Checklist
Best of Week · Agent Safety The Minimum Viable Agent-Safety Stack: Identity, Budget, Provenance, Telemetry

This week's tip thread — Monday's spec front-door, Thursday's on-device ZDR tier, and Friday's least-privilege subaccount + loop-budget + RAG-provenance — converges on one deployable stack. Layer 1, Identity: issue each agent a scoped subaccount or per-agent key (mirroring Binance Agent OS), never full account credentials. Layer 2, Budget: a max-tool-call ceiling, a token/cost cap, and an explicit termination predicate (goal-met or human-approval gate for writes). Layer 3, Provenance: retrieval as a cited tool call with source IDs in every answer. The new fourth layer — Telemetry: emit a structured span (OpenTelemetry) per tool call carrying agent_id, tool, args-hash, latency, cost, and a write/deny flag, so every agent action is queryable after the fact. The first three bound blast radius; the fourth makes the boundary auditable — which is what turns "we ran an agent" into a defensible claim for a regulated exchange. OpenTelemetry docs →

AI × iOS · Client-Side Containment Mirror the Server-Side Subaccount Boundary Client-Side: Per-Agent Keychain Scope + Scoped URLSession

Binance Agent OS scopes agents server-side via subaccounts; the iOS client should mirror that boundary, not dissolve it. Concretely: give each agent a dedicated Keychain access group (or a SecAccessControl-guarded key) instead of the app's shared keychain, hand it a short-lived per-agent token via a scoped URLSession pinned to a base URL with an allowlisted path set, and route every agent-initiated network call through that session. A prompt-injected agent then can't reach arbitrary endpoints — if its session is scoped to a read-only market-data path and its keychain entry has no payment scope, a malicious retrieved doc can't exfil funds. Pair with the telemetry span from today's first tip so the client logs every scoped call. URLSession docs →

Agent Infra · Evals Add a Regression Eval Gate Before a Write-Capable Agent Touches Production

Asana (2 weeks, ~$12K) and Stampli (68% launch-hour cut, today) show agents replacing months of engineering — but neither result is safe to ship without an eval gate. Stand up a small, frozen regression eval set (10–50 golden tasks with expected outcomes) and block agent-authored PRs that regress it; run it in CI before any merge and re-run on every model-version bump — today's GPT-5.6 Sol price cut is exactly the kind of quiet change that can shift behavior without a changelog. An eval gate is the difference between "the agent wrote it" and "the agent's change is provably non-regressive" — the latter is what a regulated team can merge at 2 a.m. Start with the riskiest surfaces (payment, signing, auth).
