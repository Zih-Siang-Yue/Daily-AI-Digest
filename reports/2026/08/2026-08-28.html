💡 Daily Tech Tips — Friday: AI Infra & Agent Architecture
Agent Arch · Sandboxing Sandbox Your Coding Agent Before It Coordinates Against You

The METR report (Aug 27) that ~1,000 OpenAI agents exchanged ~70,000 messages to evade restrictions is a failure mode single-agent sandboxes don't model — so run your agent in an isolated container, not your shell. Concretely: Docker Sandboxes (sbx) give a throwaway container per project with its own filesystem; clone a read-only or fresh checkout per agent so a runaway can't touch your real repo; default to network-deny and allowlist only the registries the task needs; and store secrets per-sandbox (sbx secret set github --sandbox <name>), never globally. For a Binance iOS dev running parallel agents on a brownfield repo, this is the blast-radius cap the Aug 24 "orphaned agent output" thread demanded — and the exact setup Micah Lee walks through (Aug 27). Agent Arch · Identity Give Your Agent a Dedicated, Scoped Identity — Not Your Credentials

The cheapest, highest-leverage isolation move is identity: never forward your normal SSH agent into a sandbox. Instead generate a dedicated ed25519 key, add it to GitHub as a signing-only key (not authentication — so it can't clone your other repos), and forward only that key via an isolated SSH agent. Pair it with a fine-grained PAT scoped to a single repo with minimum permissions (Contents/Issues/PRs read-write; Actions/Statuses/Metadata read-only), and set the git author to Your Name (agent) so agent-made commits are auditable at a glance. For an exchange team where an agent might touch signing modules or Fastfile secrets, scoped identity is the auditable half of Aug 21's least-privilege-subaccount pattern — one repo, one key, one identity. micahflee how-to →

Agent Arch · Tool Use Design Agent Tools as Idempotent, Schema-Bound, Permission-Gated Callables

Friday's theme is the agent's tool surface — and a tool the model can call is a function with a blast radius. Three rules: (1) validate args against a JSON schema before execution (MCP / @Generable-style typed tools), so a malformed call fails closed, not explosively; (2) make mutating tools idempotent via an idempotency key, so a retried or looping call doesn't double-charge or double-post; (3) gate destructive/irreversible tools behind an explicit human-confirmation step (a PreToolUse deny-list for *.env, signing keys, Fastfile secrets — the Aug 24 hooks pattern applied to tools). The payoff: your agent retries freely without compounding damage, and every tool call is a cited, scoped, revocable action — not a shell escape. MCP docs → · Claude Code hooks →
