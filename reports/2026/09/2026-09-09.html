Cursor · Rules & Context Scope the Agent With .cursor/rules + @-Context — Stop Hallucinated APIs

Cursor's Agent/Composer only knows what you feed it. Drop a .cursor/rules/*.mdc file to lock team conventions (naming, layering, test patterns) so every edit respects them, and use @codebase, @docs, @folder, and @web to hand it the exact repo slice or up-to-date docs instead of letting it guess. Payoff: fewer invented symbols, smaller diffs, reviews you can rubber-stamp. Rules docs →

Copilot · Coding Agent Assign an Issue to Copilot and Review the PR Like a Teammate

Copilot's coding agent can take a well-scoped GitHub issue, branch, implement, run tests, and open a pull request on its own. Write the issue as you would a junior's ticket (acceptance criteria + repro), then review the diff — never merge blind. Heads-up: Copilot Pro is now usage-based credits, so batch similar issues instead of spawning many agents at once. Agent guide →

Windsurf · Cross-IDE One Instructions File to Rule Cursor, Windsurf & Copilot

Each AI IDE reads a different conventions file (.cursor/rules, .windsurfrules, .github/copilot-instructions.md), so standards drift the moment someone switches editors. Keep a single source of truth and symlink or generate the per-IDE files from a repo bootstrap script — one edit propagates to all three. Cheap to set up, and it ends "the agent used the old pattern again." Windsurf →
