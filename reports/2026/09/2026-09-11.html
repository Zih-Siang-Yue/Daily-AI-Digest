💡 Daily Tech Tips — AI Infra & Prompt Engineering (RAG · Tool Use · Agent Arch)

Friday rotation. Earlier weeks already covered BM25+dense+reranker RAG, Foundation-Models guided JSON, the model-router/confidence-gating pattern, and on-device embeddings — so today goes to three agent-infra angles not yet carded.

Agentic RAG · Tool Routing Stop Always-Retrieving — Give the Agent a Retriever Tool and Let It Decide Retrieve-vs-Compute

The fixed embed query → vector search → stuff into prompt → generate RAG pipeline retrieves on every turn, even when the answer is computable, already cached, or needs a live API rather than docs. The agentic-RAG move is to expose retrieval as one tool among several (a vector-search tool, a SQL-over-truth tool, a live-API tool) and let the model route — retrieve only when its own confidence is low or the question needs fresh evidence, otherwise answer directly or call the cheaper tool. Pair the loop with an explicit iteration/token budget so a hesitant model can't spiral. Why it matters: for a Binance iOS feature (in-app support search, docs Q&A) this cuts latency and cost on the ~60% of queries that don't need retrieval, and it's the cloud counterpart to the on-device embedding store (Sep 6) — the agent earns the right to skip the retriever. Tool Use · Structured Outputs Force Tool-Call Arguments Through a Strict JSON Schema — Reject Malformed Calls Before They Break the Loop

The failure mode that quietly kills agent loops is a malformed tool call: the model emits a missing field or a wrong-type value, the tool throws, and the agent recovers badly or loops. The fix is strict-mode function calling — OpenAI strict schemas, Anthropic tool-use with JSON-schema validation, or Apple Foundation Models' guided generation — declare each tool's argument schema once, force conforming JSON, and reject + re-prompt on any schema violation at the harness boundary rather than letting a bad call propagate. Why it matters: for a Binance agent that books trades or moves funds, strict tool schemas are the type-safety layer that turns "the agent almost did the right thing" into "the agent literally cannot call the tool wrong" — the guardrail that makes bounded autonomy possible (cf. the agent control plane, Sep 5). Agent Arch · Observability Emit a Span Per Agent Step (Plan → Tool → Observe → Reflect) — Debug the Agent Loop Like You Debug a Request

When an agentic feature ships a wrong result, "the model messed up" isn't a post-mortem you can act on — you need to see which step went wrong. Instrument the loop with a span per phase (plan, tool-call, observation, reflection) carrying the input, the tool name, the raw output, and the token/cost delta, exported to the same tracing backend (OpenTelemetry) as your services. Pair it with an eval gate — a fixed set of agent tasks with expected outcomes — so a regression shows up as a failing eval, not a user ticket. Why it matters: for a Binance team running agents in prod, per-step tracing + an eval suite is the difference between "agentic feature we can ship" and "agentic feature we can debug after it ships" — the observability layer behind the verification-driven-development pattern carded below.
