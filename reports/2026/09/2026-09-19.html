Prompt Caching · FinOps Architect Prompts as Cache Keys — Layer Static→Dynamic and Turn Repeated Context Into ~90% Cost/Latency Cuts

Anthropic cache_control and OpenAI prompt caching let you mark stable prompt prefixes — system rules, tool/MCP schemas, long RAG/memory context — as cacheable, so the provider reuses the KV-cache across turns instead of re-computing it; the prompt becomes a hierarchical stability stack (static invariant prefix → tool schemas → long-term memory/RAG → volatile turn suffix) with cache breakpoints at each stable boundary. Why it matters: it's the architectural primitive behind Friday's RAG-as-infrastructure tip (the cached prefix is the retrieved context) and the FinOps answer to the cost-aware/token-economic architecture concept (Sep 14) — a 20-turn agent loop's biggest cost driver becomes a near-free prefix, and the hit rate is directly observable (cf. today's OTel tip). How to use it: order prompts strictest-stable-first, place cache_control at each stable boundary, append (don't restructure) prior agent history so the prefix survives, and target a >70% cache-read rate on multi-turn sessions. Evals · CI Gate Build a Golden-Set Trajectory Eval + CI Regression Gate — Don't Ship an Agent Change Without It

Final-answer metrics (BLEU, semantic similarity) miss agent failures — redundant tool calls, schema violations, infinite loops — so production teams run trajectory evals that grade the reasoning path against a golden set of multi-turn scenarios, as a CI gate before any prompt, model, or tool change merges; the two-track shape is offline CI gates (multi-turn scenario benchmarks against mock environments) plus online runtime guards (lightweight SLMs + deterministic Pydantic/Zod validators inspecting outputs sub-200ms). Why it matters: it's the "tests for agents" counterpart to verification-driven development (Sep 11) and the discipline the Cursor 6×-PR review-ceiling datapoint (Sep 14) makes non-optional — when the agent authors faster than humans review, the eval gate is the only thing catching regressions pre-merge. How to use it: curate 20–50 golden multi-turn scenarios, score trajectory (tool-call accuracy, schema adherence, no-loop, latency SLA), block merge on regression beyond a threshold, and add synthetic user-agents that inject prompt-injection/ambiguity to stress-test before production. LangSmith evals → · RAGAS →

Observability · OTel Emit OpenTelemetry GenAI Spans for Every Tool Call + Reasoning Step — Standardize Agent Tracing Before You Need It

Agent traces are converging on the vendor-neutral OpenTelemetry GenAI / OpenInference semantic conventions — each span carries model version, prompt hash, cached-vs-uncached tokens, tool IO, retries, and step-level cost — so a 1,000-span multi-agent run renders as an interactive DAG (Langfuse, Arize Phoenix, LangSmith) you can debug and replay, instead of an opaque monologue. Why it matters: it's the standardized successor to the per-step tracing tip (Sep 11) — vendor-neutral conventions mean your traces aren't locked to one platform, and the cached-token attribute closes the loop with today's prompt-caching tip (you can see your hit rate as a span attribute, not a monthly invoice surprise). How to use it: instrument each tool call + model call as an OTel span with GenAI attributes, ship to any OTLP-compatible backend, and visualize the orchestrator→worker delegation as a DAG so a sub-agent drift is one click to the exact span — then feed failing traces back into the eval set (today's feedback-to-eval concept). 🔥 Hot Industry Concepts

Three architectural concepts trending in the production-agent discourse — all three fresh (none carded Sep 1–18), all three forming a coherent "make agent runs cheap, measurable, and continuous" trio that extends today's best-of-week tips: the LLM gateway (where routing + caching + FinOps converge), memory-augmented agents (persistent cross-session memory beyond the context window), and the feedback-to-eval closed loop (production failures auto-feed the eval set).

Infra · Routing LLM Gateway / Model Routing — One Entry Point for Multi-Model Routing, Warm-Cache Affinity, Fallback, and Cost Caps

The LLM-gateway pattern (LiteLLM, vLLM routers, custom Envoy extensions) places a single gateway in front of your model fleet: it routes each request to the right model, uses RadixAttention-style prefix matching to route to workers with warm KV-caches for that session (maximizing today's prompt-caching tip's hit rate), falls back across providers on outage, and enforces per-workspace cost caps. Why it matters NOW: it's the architectural container for the prompt-caching tip + the model-cascading concept (Sep 17) + the cost-aware architecture (Sep 14) — the gateway is where routing, caching, fallback, and FinOps converge, and it's the layer that makes a multi-vendor agent fleet (Claude + GPT + Gemini + local SLM) operable rather than chaotic. How to use it: stand up LiteLLM (or similar) as the single entry point, enable prefix-cache-aware routing, configure provider fallback chains, and set per-team spend caps that BLOCK on trip. LiteLLM →

Memory · Long-Term Memory-Augmented Agents — Persistent Cross-Session Memory (mem0 / Letta) Beyond the Context Window

Production agents are moving from "stateless per request" to memory-augmented architectures (mem0, Letta/MemGPT) that persist a structured long-term memory store across sessions — episodic logs, semantic facts, user preferences — that the agent retrieves and writes to independently of the context window, so a returning user's agent remembers prior interactions without re-stuffing them into the prompt. Why it matters NOW: it's the layer beyond the context-engineering tier (Sep 15) — context budgeting manages what's in the window; memory-augmentation manages what's persisted across windows — and it's the substrate that makes a Binance in-app assistant feel continuous (remembers your portfolio questions, your risk preferences) rather than amnesiac per session. How to use it: add a memory layer (mem0 for managed, Letta for self-hosted) that writes salient facts per turn and retrieves top-k relevant memories at session start; gate writes with the deterministic-guardrail sandwich (Sep 18) so the agent can't persist poisoned/prompt-injected content. mem0 → · Letta →

Evals · Continuous Feedback-to-Eval Closed Loop — Production Traces With Failures Auto-Tagged Into the Offline Eval Dataset

The closed loop connects the observability plane to the eval plane: production traces with high latency, negative user sentiment, or failed step assertions are automatically tagged and ingested into the offline eval dataset, so every production failure becomes a regression test — forming a continuous fine-tuning and prompt-regression loop rather than a static golden set. Why it matters NOW: it's the continuous-improvement complement to today's eval-harness tip (the gate) — the gate catches regressions pre-merge, the loop grows the eval set from real failures post-merge — and it's the architecture that keeps an agent's quality from silently rotting as the world (and the model) drifts; it ties the OTel observability tip (traces) to the eval tip (regressions) into one self-improving system. How to use it: instrument traces with success/failure labels (user feedback + assertion failures), auto-export failing trajectories to your eval dataset, and run the eval gate on every agent change against the growing set — the loop makes the eval set self-curating.
