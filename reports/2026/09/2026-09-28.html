💡 Daily Tech Tips — Claude Code / Codex (Hooks · MCP · Skills)
Claude Code · Hooks Gate Side-Effects With PreToolUse / PostToolUse Hooks — the Deterministic Boundary at Execute Time

Claude Code hooks let a script intercept a tool call before or after it runs: a PreToolUse hook on Bash can match the command against a deny regex and exit non-zero to block the call (or emit JSON on stdout to rewrite it); a PostToolUse hook on Write/Edit runs your formatter + linter and can post the diff to the PR. Why it matters: it’s the execute-time gate the “deterministic sandwich” (Sep 16/25) needs — the model can ask for a shell command, but a hook enforces the allowlist in code the model can’t talk its way past (cf. the Australia agent-hack Sep 25). How to use it: declare hooks in .claude/settings.json keyed by tool name + event, keep hook scripts fast + idempotent, and log every block/rewrite so the guardrail is auditable. Claude Code hooks →

Claude Code · MCP Scope MCP Servers Per-Project & Deny-by-Default — the Tool-Surface Least-Privilege Move

Wire only the MCP servers a project actually needs in .mcp.json, namespace every tool by its server (mcp__github__create_issue), and expose only the tool sub-list each agent may call via the harness allowlist — never grant the full server surface and hope the prompt restrains it. Why it matters: it’s the least-privilege answer to the “every agent has an open tool surface” problem the Databricks Unity Gateway move (today’s AI card) operationalizes at enterprise scale — and for an iOS dev it’s how you let a release-notes agent read Jira without also letting it push a tag. How to use it: enumerate servers per-project, surface the allowed tool sub-list in AGENTS.md (Sep 21), and audit actual calls against the allowlist via the hook log. Claude Code MCP →

Claude Code · Skills Package Reusable Skills as Semver-Tagged Bundles in .claude/skills/

Wrap a (prompt fragment + allowed MCP tools + eval script) into a Skill under .claude/skills/<name>/SKILL.md with frontmatter (name, version, allowed-tools), pin the version per-project, and treat a skill bump as a reviewed PR — so every agent run uses the identical skill, and a skill edit can’t silently change behavior across repos. Why it matters: skills become the agent-native reuse unit (the npm-package analog), and version-pinning is what stops the “the agent worked yesterday” class of regression that pure prompt-editing creates. How to use it: define one skill per repeatable workflow (e.g. “release-notes-from-jira”), reference it from AGENTS.md, and add a skill-version: tag to each PR so skill drift is visible. Anthropic · Claude Code

Claude Code Projects Redesigned as a Coordinator-Led Agent Swarm — Parallel Cloud Sessions + Autonomous PR Merge

Anthropic rearchitected Claude Code Projects from single-session terminal runs into a multi-agent topology: a central coordinator agent decomposes a large task into parallel cloud sessions on separate branches, reviews the diffs, and merges the pull requests autonomously. It also added a Claude Design bridge for two-way sync between a design system and the live UI repo. Why it matters: it’s the topology shift past the “multi-threading + persistent memory” Claude Code coverage from Sep 18/25 — the agent now owns the merge, not just the write, so the human gate moves to plan approval and post-merge verification, not line-by-line review. How to use it: enable on one bounded multi-file task with a required-green-tests + code-review status gate before the auto-merge; keep the coordinator’s tool allowlist narrow (today’s tip #2). (Caveat: WebSearch-sourced; verify on docs.anthropic.com.)

Databricks shipped enterprise governance controls letting orgs centrally configure coding agents — enforcing permitted models, allowed MCP servers, available tool skills, agent harnesses, and Smart Routing via the Unity Gateway CLI or enterprise MDM, alongside adding Databricks-hosted GPT-6 Astra, GPT-6 Sol, and Google Gemini 3.8 Flash to its Foundation Model APIs. How to use it: scope one team’s agents through Unity Gateway, treat the policy file as the source of truth (mirror into AGENTS.md), and alert on any agent run that bypasses the gateway. 🔧 Vibe Coding & Dev Tools
Agent Orchestration

Agent Fleet Orchestrators — Superset, Capy & Antigravity Manage Parallel Agents Across Branches/Worktrees

The new tool tier above the single-agent IDE: orchestrators like Superset, Capy, and Antigravity dispatch fleets of concurrent agents across separate git branches/worktrees, each running tests and submitting independent PRs. Why it matters: it’s the step past Claude Code’s coordinator-swarm (today’s AI card) — where Claude Code’s coordinator runs inside one tool, fleet orchestrators run across tools and repos, and the human’s job becomes reviewing the PR queue, not any single agent. How to use it: start one fleet run on a low-risk repo with a per-agent branch-naming convention and a shared AGENTS.md; never auto-merge fleet PRs. (Caveat: WebSearch-sourced.)

Trust & Verification

The Production-Trust Gap Closes — Integrated Security Scanning + Synthetic Unit-Test Gen + PR Verification Agents Become IDE-Standard

After a year of CVE reports on vibe-coded MVPs (missing auth checks, leaked secrets, ghost deps), the major AI IDEs are converging on a trust stack: integrated secret/dependency security scanning, synthetic unit-test generation on every diff, and a dedicated PR-verification agent that re-checks the change against the task spec before merge. Why it matters: it’s the structural counterweight to the “maintenance debt” concept carded Sep 25 — trust stops being a review-time activity and becomes a build-time gate, which is what makes an agentic-CI/CD loop (Sep 23) safe to run unattended. How to use it: enable the security scan + synthetic-test gen as required status checks; treat the PR-verification agent’s “spec match” report as a merge gate, not a suggestion. Security · Rollback

Zano Rolls Its Blockchain Back a Month After a Gateway Address Exploit — a Rare Hard-Fork Reversal

Privacy-focused chain Zano restarted at the block height immediately before Hard Fork 6 (which introduced “Gateway Addresses”) after an exploit abused the feature (Sep 28, RSS-verified Cointelegraph) — effectively rewinding a month of onchain history to undo the damage. Why it matters: a full chain rollback is the nuclear option exchanges/wallets must plan for but rarely see exercised; it voids every transaction in the rolled-back window, so any swap/withdraw/deposit a reader’s system recorded in that range can become disputed. How to use it: ensure your reconciliation pipeline can re-process a reorg window for any chain you list, and treat “exploit → rollback” as the threat-model entry on your listing risk register, not just “exploit → freeze.” (RSS-verified; Cointelegraph, real Sep 28 URL.)

🔥 Hot Industry Concepts
Architecture The Coding-Agent Governance Plane — Policy-over-Agents as a First-Class Platform Layer

As every team runs multiple coding agents (Claude Code, Codex, Cursor, Copilot) the policy layer — which models may be used, which MCP servers exposed, which tools callable, which harness version, with what routing — is converging into a distinct platform concern: the coding-agent governance plane, enforced centrally (Databricks Unity Gateway is today’s instance) and mirrored per-repo in AGENTS.md. Why it matters NOW: it’s the platform answer to the “every agent has an open tool surface” risk the Australia incident (Sep 25) made concrete — where IAM scopes said which tool (Sep 22) and ReBAC says which row (Sep 25), the governance plane says which agent may use which model+tool at all. How to use it: treat the policy file as the source of truth; lint it in CI; alert on any agent run that bypasses the gateway. Databricks Unity Gateway →

Reuse · Agents Agent Skills as Versioned Artifacts — the npm-Package Analog for Agent Behavior

The emerging reuse unit for agents is the Skill: a self-contained bundle of (system-prompt fragment + allowed-tools + eval set) that’s packaged, semver-tagged, and registered so any agent run can pin a specific version — the agent-native analog of an npm package, where the skill (not the raw prompt) is what you version, review, and roll back. Why it matters NOW: it’s what turns one-off prompt-engineering into a reviewable dependency surface; a skill bump becomes a PR with an eval delta, and a regression is a one-line roll-back in the pin. How to use it: define skills under .claude/skills/<name>/SKILL.md with a version field, commit the eval results alongside the bump, and reference the pinned version from AGENTS.md. Skills docs →

Memory · Debuggability Event-Sourced Agent Memory & Replay — the Append-Only Log That Makes a Failed Run Debuggable

Distinct from Claude Code’s persistent project-fact memory (Sep 25), event-sourced agent memory models every state change (tool call, env observation, message) as an append-only event on a per-run log; replay the log to reproduce a failure, branch it to test a fix, or snapshot it for audit. Why it matters NOW: it’s the memory-layer complement to the agent-choreography/event-bus concept (Sep 26) — where choreography says how agents talk, event-sourced memory says how a single agent’s run is reconstructed, and for a regulated-finance reader it’s the “what did the agent do, in order, and why” answer an auditor will eventually ask. How to use it: emit a structured event per tool call (input, output, model, tokens); store immutable; debug by replaying the exact run. Building effective agents →
