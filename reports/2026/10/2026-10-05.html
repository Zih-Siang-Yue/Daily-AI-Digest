💡 Daily Tech Tips — Claude Code / Codex Agentic Workflow (Hooks · MCP · Skills)
Claude Code · Skills Ship Each Skill as a Failing-Test-First Spec, and Gate Install Behind Its Own Green Run

Make the skill a versioned artifact whose frontmatter declares an acceptance test, then block auto-install with a PostToolUse hook that runs the test before the skill registers — so a skill lands only when it can prove itself, not when it’s cited. Why it matters: a skill is a capability artifact (Sep 28); without an install gate a stale or broken skill silently pollutes the agent’s tool surface, and Claude Code 2.1’s auto-resume (Oct 4) means a broken skill now survives an unattended run. How to use it: write the test first, ship the skill with acceptance: ./tests/skill.sh in its manifest, and treat a red result as a hard stop — never let the agent self-promote a skill to trusted without the test green. Claude Code · Hooks Wire a Stop Hook as the Deterministic Sandwich for Every Unattended Run

Inject lint + typecheck + test as a Stop hook that runs after each edit pass and writes the result as a <system-reminder> block the model must read before its next turn — exit 2 blocks and forces a fix. Why it matters: persistent coordinator swarms (Sep 28) plus auto-resume (Oct 4) made the multi-hour refactor real this week; a Stop hook that fails the run on red is the only thing keeping a flaky edit from compounding across 50 steps. How to use it: emit the hook output as a gate (never advisory), log every gate decision as an OTEL span (Sep 30), and treat the span trail as the compliance artifact for agent-initiated edits. Codex · MCP Tier Your MCP Servers — stdio-Local Always-On, HTTP-Remote Per-Session OAuth

Put local stdio MCP servers (filesystem, git, shell) on the always-on list and remote HTTP servers (Jira, Linear, Notion) behind per-session OAuth scopes declared in .mcp.json — never let one server hold the whole tool surface. Why it matters: the governance plane (Sep 28) is enforced one server at a time; a single monolithic MCP server with a blanket token is the flat-permission anti-pattern that turns a prompt-injection into a full breach — the exact failure mode the eBPF sandbox (Oct 3) is the kernel-side floor for. How to use it: declare per-server scopes, rotate tokens via a refresh hook, and never let a remote server share a scope with a local one; treat the .mcp.json allowlist as the audited IAM artifact.
