AI × iOS · Decode Strategy Route by KV-Cache Shape — ANE Fixed-Window Prefill, MLX GPU Decode Tail

The ANE’s power edge comes from static, compiled graphs; autoregressive KV-cache growth breaks that compilation and silently falls back to CPU/GPU, throwing away the efficiency win. Why it matters: this is the failure mode that makes a “Core ML LLM” benchmark great in CI and terrible in a warm pocket — and it’s the depth-layer behind Tuesday’s ANE+GPU concurrency tip. How to use it: bucket the KV cache in fixed windows (e.g. 128/256 tokens) so prefill stays on the compiled ANE path, and hand only the dynamic decode tail to MLX/Metal — treat the window size as the dial that trades cache memory for ANE residency. Edge AI · Open Weights Skip coremltools Entirely — Load mlx-community 4-bit Checkpoints Straight Into mlx-swift

For shipping an open SLM (Qwen-2.5-Coder-3B, Gemma-2-2B) on iOS, the fast path is pulling a pre-quantized mlx-community checkpoint into mlx-swift arrays — no static-graph export, no conversion latency, full control of the token loop and sampling. Why it matters: it inverts Tuesday’s .mlmodelc pre-compile tip — when you need dynamic shapes or custom attention, Core ML’s AOT graph is the obstacle, not the asset, and native MLX group-quant keeps the model under the 2–2.5 GB jetsam budget. How to use it: pin a 4-bit checkpoint for your floor model, load weights lazily off a memory-mapped file, and keep the system ~3B model as the cold-start fallback. mlx-community →

Core AI · Gateway Try Apple’s Core AI / Foundation Models Framework Before Raw MLX — Zero Bundle Overhead, Built-In Speculative Execution

Before reaching for MLX, evaluate Apple’s Core AI + Foundation Models framework against the built-in ~3B system model: it targets transformer architectures with native dynamic contexts and speculative execution, runs with zero app-bundle-size cost, and zero RAM allocation against your app’s memory limit. Why it matters: for summarization, extraction, and entity-recognition tasks the system model is the zero-cost default; MLX is only worth the weight when you need custom weights or sampling control. How to use it: prototype against the system model first, and only promote to MLX when the task demands a specific open model — the Foundation Models API is the gateway that precedes Tuesday’s hybrid pattern.
