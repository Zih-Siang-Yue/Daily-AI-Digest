💡 Daily Tech Tips — Claude Code & Codex (agentic workflow · hooks · MCP)
Claude Code · Subagents Spawn a Subagent With a Scoped Tool Allowlist — Capability Sandboxing, Not Just Worktree Isolation

The /agents command lets you define a named subagent with its own system prompt and a restricted tool set — e.g. a “test-writer” that only gets Read, Edit, and a sandboxed Bash, no git push or rm. Why it matters: the worktree-per-agent pattern (Oct 7/11) isolates files; scoped tool allowlists isolate capabilities — the two compose, so a derailed subagent can edit its branch but cannot push, force, or shell out. How to use it: declare one subagent per repeatable chore (migration, test-gen, doc-sync), pin its allowed_tools, and treat the allowlist as code — review it in PRs, never inline-edit. Claude Code · Hooks Wire a PostToolUse Hook to Auto-Run the Affected Test Target — Close the Agent Test Loop

The PostToolUse hook event fires after every file edit — point it at a script that maps the edited path to its test target and runs it, piping pass/fail back into the agent’s context. Why it matters: the prior hook tips gated input (PreToolUse Stop, Oct 5; Blast Radius, Oct 1); this closes the output side — the agent sees a red test in the next turn and self-corrects, so the test loop runs inside the agent, not in a separate terminal you forget to watch. How to use it: register the hook in .claude/settings.json for PostToolUse on Edit|Write, keep the test runner fast (<10s) or the agent stalls, and fail the hook on test-error so the verdict is unambiguous. Hooks docs →

MCP · Sampling Let Your MCP Server Borrow the Client LLM via sampling/createMessage — No Extra API Key

MCP’s lesser-known sampling primitive lets a server request an LLM completion from the client (Claude Code/Cursor), so server-side agentic logic (summarize a query result, classify a row, pick a tool) runs on the user’s already-paid session — no separate API key, no separate bill. Why it matters: prior MCP tips covered tiering servers by trust (Oct 4/5); sampling is the inverse direction — the server calls up to the host model — and it is the primitive that lets a custom MCP server do real reasoning without shipping its own credentials. How to use it: expose sampling/createMessage in your server, have the client approve the callback, and keep prompts small — the server pays in the user’s tokens. MCP sampling →
