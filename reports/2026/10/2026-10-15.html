💡 Daily Tech Tips — Edge AI / On-Device ML (ANE · MLX · ExecuTorch)
ANE + GPU · Hybrid Scheduling Co-Schedule LLM Prefill on ANE and Decode on GPU — Stop Running Everything on One Engine

Prior tips covered ANE fixed-window prefill (Oct 10) and MLX dynamic decode (Oct 13) as separate paths. Today: run them together. Apple's runtime already dispatches static layers (embeddings, vision encoders) to the ANE via Core ML and dynamic autoregressive decode to the GPU via MLX — unified memory lets them share weights without copies. Why it matters: a Binance iOS dev running a 3B SLM purely on MLX/GPU leaves the ANE idle and burns 5–10x more battery per token; routing prefng.pngill to the ANE and decode to the GPU delivers the best tokens-per-watt. How to use it: export the embedding + encoder layers as .mlpackage for ANE, keep the transformer blocks in MLX for GPU decode, and profile the handoff with os_signpost to verify zero-copy weight sharing. ExecuTorch · Cross-Platform Use ExecuTorch's Core ML Backend to Ship One Model for iOS and Android

Meta's ExecuTorch (PyTorch Mobile) now features an optimized Core ML backend that dispatches directly to the ANE, so you write one model export and run it on Apple Silicon natively. Why it matters: prior iOS tips (Oct 10–13) assumed you either use Core ML or MLX; ExecuTorch gives a third path for teams that need cross-platform parity — same graph, same quantization, but the Core ML delegate handles the ANE compilation on iOS while the XNNPACK delegate covers Android. How to use it: export via torch.export, register the Core ML delegate, and benchmark against your hand-tuned .mlmodelc to confirm the overhead is acceptable before committing. ExecuTorch →

Speculative Decoding · Latency Cut On-Device SLM Decode Latency 2–3x With Speculative Decoding From a Tiny Draft Model

Pair a 0.5B draft model with your main 3B model: the draft model generates candidate tokens cheaply, the main model verifies them in a single forward pass, and accepted tokens bypass the decode loop entirely. Why it matters: prior tips optimized prefill (Oct 10) and training (Oct 13) but not decode latency — and decode is memory-bandwidth-bound on mobile, so a 2–3x speedup directly improves perceived UX for on-device chat/summarization features without sacrificing quality. How to use it: quantize the draft model to 4-bit, keep the main model at 4–6 bit, and ensure both fit in unified memory with headroom for the UI; profile rejection rates to tune draft size. Janas — Open-Source MoE Inference Engine Streams Expert Weights From NVMe SSDs

Janas is a new open-source inference engine designed to run large mixture-of-experts (MoE) models beyond local RAM capacity by dynamically streaming expert weights from high-speed NVMe SSDs — an 80B-parameter model can run on a 32 GB machine. Why it matters: as MoE architectures dominate the frontier model landscape (GPT-6, Mixtral, Qwen MoE), the ability to run them locally without shelling out for 128GB+ of RAM is the edge-AI democratization moment — and it pairs naturally with the on-device routing pattern (Oct 14) for hybrid dev setups. How to use it: benchmark a sub-30B MoE on your dev machine, compare latency vs API calls over a sprint, and treat NVMe streaming as a middle tier between pure-local and cloud.
